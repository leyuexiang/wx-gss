### 已落地

- 复用工作区已有 `app/capture/contracts.py` 与 `quality.py`，保留采集描述、前景摘要、位姿摘要和质量检查接口。

- 已存在的协议拒绝覆盖；旧素材无提供器记录时标记 `legacy_unspecified`，无拍摄模式识别时标记 `unknown`，不伪造历史信息。
- 实验准备入口显式启用注册率和重投影误差门禁，普通流水线默认仍关闭。失败时先写完整报告，再中止整理训练图像。
- 门禁拒绝非有限帧率、布尔面积比例及负重投影误差等异常输入。

## 2026-10-29：相机组内共享修正与真实几何验证

### 问题及修改

旧的特征分组为每组单独运行工具，但仍传入 `single_camera=0`，实际产生了 122 个相机，每张图独立内参。它与视频组共享设计不一致，是已确认的实现问题；此前仅将破损归因于分辨率、反光或采集并不充分。

修正为每组独立启动特征提取并设置 `single_camera=1`。在当前服务器 COLMAP 3.11.1 的真实小样本验证中，同组视频共用相机，跨进程的顶部、底部各创建独立相机。普通不分组任务仍沿用原来的共享模式。

新增 `app/capture/camera_groups.py`：

- 检查全部原图恰好出现一次、组内尺寸一致、焦距与内参数值有效。
- 保留统一裁切后的实际主点，允许其位于裁切图外，不改为裁切图中心。
- 分组任务拒绝使用已有数据库，防止错误旧内参被静默复用。
- 特征提取结束后只读核查数据库：组内相机 ID 相同、组间相机 ID 不同、实际尺寸与内参符合声明。
- 核查通过后写 `colmap/camera_groups.json`，其摘要及内容会随新训练的 `protocol.json` 保存。该记录明确是几何优化前的初值；联合优化允许修改内参。
- 数据库连接显式关闭，Windows 定向测试发现的文件句柄未释放问题已修复。

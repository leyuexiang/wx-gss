# 通用训练框架验收记录

## 2026-10-29：M0 首批实现

本批完成通用接口的首个可运行切片，尚未完成整个 M0，更不代表通用分割或跨素材画质已通过。

### 已落地

- 复用工作区已有 `app/capture/contracts.py` 与 `quality.py`，保留采集描述、前景摘要、位姿摘要和质量检查接口。
- 新增 `app/foreground/`，统一粗分割、细化分割和算法来源描述。白罐、红罐、灰桌面金属圆面作为三个显式插件；未知插件直接拒绝，不按文件名猜测颜色。
- 两个准备脚本仍保留历史函数导入和命令行参数，算法阈值、图割尺度及裁切方式保持不变；新增掩码包含提供器名称、版本、适用范围和未复查标记。
- 新增 `app/capture/provenance.py`。实验训练入口开始前校验实际掩码摘要和图像尺寸，冻结 `protocol.json`，记录每张实际训练图的尺寸、摘要、掩码来源、训练选项和关键源码摘要。
- 已存在的协议拒绝覆盖；旧素材无提供器记录时标记 `legacy_unspecified`，无拍摄模式识别时标记 `unknown`，不伪造历史信息。
- 实验准备入口显式启用注册率和重投影误差门禁，普通流水线默认仍关闭。失败时先写完整报告，再中止整理训练图像。
- 门禁拒绝非有限帧率、布尔面积比例及负重投影误差等异常输入。

### 验证证据

1. 本机定向检查：8 项测试中 7 项通过、1 项因缺少重建依赖跳过。服务器完整依赖环境执行全部 54 项测试通过。
2. 对比迁移前 Git 版本的算法与新适配器，使用白罐 3 帧、红罐 3 帧、顶部和底部各 1 张，共 8 张真实图；固定图割随机种子后，最终掩码逐像素一致。报告保存在服务器 `quality-framework-m0-20261029/adapter_parity.json`。
3. 使用红罐任务 `9ad16d63b8ed4036a5f4ed241dace3d2` 的冻结数据进行 100 次独立流程检查，检验协议冻结、前景训练、标准模型导出、验证和打包；原任务不改动，短训练不发布到模型列表，也不用来判断画质。
4. 测试和短训练源码置于 `/data/quality-framework-m0-20261029`。本批没有重训或替换历史推荐模型，也未部署生产默认流水线。

真实掩码相同仅证明迁移兼容，不证明掩码正确。注册率与重投影误差也不能证明三维完整性；视角覆盖、反射诊断、分区域轮廓检查尚未统一接入。

### 尚未完成

- 输入、抽帧、位姿和评估仍主要由现有函数承担，未全部迁移成独立适配器。
- 原始解码视频与衍生兼容副本的完整变换链、准备阶段源码摘要尚需统一；本批协议记录当前训练源码和已选图来源，不声称追溯了未知的历史准备代码。
- 拍摄模式自动识别、通用分割模型、人工关键帧传播和生产接口配置尚未实现。
- 角度覆盖门禁和训练后发布门禁尚未接入；当前实验显式关闭未计算的角度检查，不将其报告为通过。
- 未人工复查掩码仍只允许显式隔离实验，新的接口不会自动把它们转为人工真值。

### 下一批优先项

1. 修复并实际核验相机分组：上一轮红罐视频逐帧生成独立内参，与计划中的共享视频内参不一致；先测试同组共享、跨组隔离、裁切主点和补拍照片内参，再做独立几何对照。
2. 为抽帧、重建和训练建立贯通的输入/输出协议，补充缺失诊断项的阻断或待复查状态。
3. 再推进通用分割、掩码关键帧确认和质量报告展示。新模型的画质改善必须另做冻结输入对照，不能以本批接口迁移代替。

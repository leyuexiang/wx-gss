# 3DGS 清晰度优化第四轮记录

日期：2026-10-27。承接 [第三轮记录](3DGS清晰度优化第三轮记录.md)，本轮开始处理主体掩码和背景漂浮。

## 1. 掩码原型

新增 [prepare_subject_masks.py](../scripts/prepare_subject_masks.py)，使用冻结的主体矩形和参考图 SHA-256 摘要，生成 OpenCV GrabCut 前景掩码。脚本输出逐帧 PNG、接触图和前景覆盖率报告；参考图发生变化或标注缺失时直接失败。

本次茶罐七张验证图的前景覆盖率为 18.5%–36.2%。接触图保存在服务器 `/data/quality-audits/subject-masks-prototype-20261027/mask-contact.png`，本机复制为 `data/quality-audits/subject-masks-prototype.png`。

## 2. 当前结论

原型可以抓住罐盖、罐身的大部分轮廓，但部分图像把罐底相邻的白色桌面连入前景；第 56 帧主体还在画面边缘被截断。它不是人工分割真值，不能直接作为训练掩码，也不能据此宣称背景漂浮已经解决。

因此当前不把 GrabCut 输出接入默认训练流程。下一步应先进行少量人工边缘修正，或者改用经过人工检查的分割模型，再在同一 7,000 次配置上与无掩码基线做对照。对照必须同时记录主体指标、全图指标、背景误差和新增漂浮点，不能只看主体区域 PSNR。

## 3. 后续顺序

1. 修正七张留出图以及训练图的掩码边缘，优先处理罐底桌面误分和出画视角。
2. 将掩码作为可选数据输入，默认关闭；训练和评估记录掩码摘要、覆盖率与版本。
3. 先跑短训练流程检查掩码是否改变相机、点云初始化和显示，不直接覆盖当前推荐模型。
4. 在相同 7,000 次、60 视角和冻结验证集下比较有无掩码；只有全图不明显回退且背景漂浮减少，才考虑纳入高质量模式。

曝光一致性放在掩码对照之后。当前手机视频的桌面高光和金属罐盖反光仍会限制可恢复的视角相关颜色，增加训练次数不能补回拍摄时缺失的信息。

## 1. 项目概述

### 1.1 项目定位

3DGS 训练服务是一个**端到端的 3D 高斯点云生成服务**，将多视角照片转换为可交互的 3D 模型（3D Gaussian Splatting 格式）。

**核心能力**：
- 多视角照片 → 相机位姿估计（SfM）→ 高斯点云训练 → 3D 模型导出
- 支持**密集拍摄**（20-500 张）和**少视角**（2-15 张）两种场景
- GPU 加速的完整流水线（COLMAP GPU SIFT + gsplat CUDA 训练）
- 异步任务管理 + RESTful API

### 1.2 应用场景

- 文物数字化保护
- 电商商品 3D 展示
- 房地产虚拟看房
- 游戏/影视资产制作
- VR/AR 内容创建

### 1.3 技术亮点

1. **双 SfM 后端架构**：COLMAP（高精度）+ MASt3R（少视角容忍）
2. **GPU 全流程加速**：COLMAP GPU SIFT（4-7× 加速）+ gsplat CUDA 训练
3. **智能显存管理**：动态降采样 + 高斯数量上限控制
4. **容器化部署**：Docker Compose 一键启动，支持水平扩展

### 3.2 功能模块详解

#### 3.2.1 API 服务（main.py）

**职责**：
- RESTful 接口暴露（/train, /train/{task_id}, /train/{task_id}/result）
- API Key 鉴权（X-API-Key 请求头）
- 参数校验（图片数量、训练参数范围）
- 任务提交到 Celery 队列
- 状态查询（读取 status.json）

**核心接口**：

| 端点 | 方法 | 功能 | 鉴权 |
|------|------|------|------|
| `/health` | GET | 健康检查（Redis 连通性、磁盘空间） | 否 |
| `/train` | POST | 提交训练任务 | 是 |
| `/train/{task_id}` | GET | 查询任务状态 | 是 |
| `/train/{task_id}/result` | GET | 下载结果 ZIP | 是 |
| `/train/{task_id}` | DELETE | 删除任务 | 是 |

**安全设计**：
- 路径穿越防护：task_id 严格校验（仅允许十六进制字符）
- 资源隔离：每个任务独立目录
- 运行时保护：运行中的任务禁止删除

#### 3.2.2 训练流水线（pipeline.py）

**流程编排**：

```python
def run_pipeline(task_id, iterations, downsample, cap_max, status_cb, sfm_backend):
    """
    完整训练流水线：
    1. 解压图片包 → images/
    2. SfM 重建（COLMAP 或 MASt3R）→ dataset/
    3. gsplat 训练 → output/
    4. 结果打包 → result.zip
    """
```

**进度分段**（0.0 - 1.0）：
- 0.00 - 0.02: 解压图片
- 0.02 - 0.40: SfM 重建（COLMAP 或 MASt3R）
- 0.40 - 0.95: gsplat 训练
- 0.95 - 1.00: 结果打包

**SfM 后端切换**：

| 后端 | 触发条件 | 流程 |
|------|----------|------|
| **COLMAP** | `sfm_backend="colmap"` | 特征提取 → 匹配 → 增量重建 → 去畸变 |
| **MASt3R** | `sfm_backend="mast3r"` | 模型加载 → 场景图构建 → 全局对齐 → COLMAP 格式导出 |

#### 3.2.3 COLMAP 重建（pipeline.py: _run_colmap）

**步骤**：

1. **特征提取**（feature_extractor）
   - SIFT 特征点检测
   - GPU 加速：`--SiftExtraction.use_gpu=1`
   - 相机模型：OPENCV（处理镜头畸变）

2. **特征匹配**（exhaustive_matcher / sequential_matcher）
   - 图片数 ≤ 300：exhaustive（全匹配）
   - 图片数 > 300：sequential（序列匹配 + 回环检测）
   - GPU 加速：`--SiftMatching.use_gpu=1`

3. **稀疏重建**（mapper）
   - 增量式 Structure-from-Motion
   - Bundle Adjustment 优化

4. **图像去畸变**（image_undistorter）
   - 输出 COLMAP 格式（cameras.bin, images.bin, points3D.bin）
   - 最大分辨率限制：2000px

**质量校验**：
- 注册率 ≥ 50%：`registered_images / total_images >= 0.5`
- 最少注册数 ≥ 20 张
- 稀疏点数 ≥ 100

#### 3.2.4 MASt3R 重建（pipeline.py: _run_mast3r）

**步骤**：

1. **模型加载**
   - 预训练权重：`MASt3R_ViTLarge_BaseDecoder_512_catmlpdpt_metric.pth`（2.75GB）
   - 设备：CUDA

2. **场景图构建**
   - 图像加载：统一 resize 到 512×512
   - 场景图模式：`complete`（全连接，适用于 <20 张图）
   - 对称化：每对图片双向预测

3. **全局对齐**（sparse_global_alignment）
   - 位姿优化：两阶段梯度下降（lr1=0.07/500 iter + lr2=0.014/200 iter）
   - 共享内参：`shared_intrinsics=True`
   - 置信度阈值：`matching_conf_thr=5.0`

4. **COLMAP 格式导出**
   - 深度图反投影 → 世界坐标点云
   - PINHOLE 相机模型（不处理畸变）
   - 输出与 COLMAP 相同的 bin 格式

**显存优化**：
- 场景图策略：
  - < 20 张：`complete`（全连接）
  - ≥ 20 张：`swin`（滑动窗口）或 `retrieval`（检索邻近）
- 点云降采样：`points_stride=2`，最多 300K 点

#### 3.2.5 gsplat 训练（trainer.py）

**训练策略**：MCMC（Markov Chain Monte Carlo）

**核心参数**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `iterations` | 7000 | 训练迭代次数 |
| `downsample` | 4 | 图片降采样倍数（1/2/4/8） |
| `cap_max` | 1,000,000 | 高斯数量上限 |
| `sh_degree` | 3 | 球谐函数阶数 |
| `lr_means` | 1.6e-4 × scene_scale | 位置学习率 |

**优化器配置**：
- **means**（位置）：Adam，lr=1.6e-4 × scene_scale，指数衰减
- **scales**（缩放）：Adam，lr=5e-3
- **quats**（旋转）：Adam，lr=1e-3
- **opacities**（不透明度）：Adam，lr=5e-2
- **sh0/shN**（颜色）：Adam，lr=2.5e-3 / 2.5e-3/20

**MCMC 策略参数**：
- `refine_start_iter`: 500（开始细化）
- `refine_stop_iter`: iterations × 0.6（停止细化）
- `refine_every`: 100（细化间隔）
- `min_opacity`: 0.005（最小不透明度）

**损失函数**：
- **L1 损失**：80% 权重
- **SSIM 损失**：20% 权重（结构相似性）

**显存优化**：
- Packed 模式：紧凑存储，省显存
- `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`：内存池动态扩展
- torch extensions 缓存：`/data/.torch_ext`（避免重复编译）

#### 3.2.6 模型导出（export.py）

**输出格式**：

1. **point_cloud.ply**（Inria 标准格式）
   ```
   [顶点属性]
   - x, y, z: float（位置）
   - nx, ny, nz: float（法向量，gsplat 中为 0）
   - f_dc_0/1/2: float（球谐 0 阶系数）
   - f_rest_{0..44}: float（球谐 1-3 阶系数）
   - opacity: float（不透明度）
   - scale_0/1/2: float（缩放）
   - rot_0/1/2/3: float（四元数旋转）
   ```
   - 格式：binary_little_endian
   - 用途：SuperSplat、PlayCanvas、Three.js 编辑器

2. **point_cloud.splat**（antimatter15 格式）
   ```
   [每个高斯 32 字节]
   - position: float16[3]（6 字节）
   - scale: float16[3]（6 字节）
   - color: uint8[4]（4 字节，RGBA）
   - rotation: int8[4]（4 字节，归一化四元数）
   ```
   - 用途：Web 端轻量查看器

3. **train_stats.json**（训练统计）
   ```json
   {
     "iterations": 7000,
     "num_gaussians": 812334,
     "final_loss": 0.03812,
     "train_seconds": 912.5,
     "peak_gpu_mem_gb": 5.4,
     "n_images": 86,
     "downsample": 4
   }
   ```

```

  ├─ file: photos.zip
  ├─ sfm_backend: colmap | mast3r

  ├─ 参数校验（图片数量、范围检查）

  ├─ 保存 input.zip → /data/tasks/{task_id}/
```

## 6. 关键技术实现

### 6.1 GPU COLMAP 加速

**问题**：COLMAP 默认 CPU SIFT，特征提取和匹配速度慢（36 张图：提取 2.47s，匹配 20.3s）

**解决方案**：
1. **源码编译 CUDA 版 COLMAP**
   - 启用 `GUI_ENABLED=ON`（保留 Qt OpenGL 上下文管理器）
   - 指定 `CMAKE_CUDA_ARCHITECTURES=89`（RTX 4060）

2. **无头 GPU 上下文**
   - 环境变量：`QT_QPA_PLATFORM=offscreen`
   - Docker：`NVIDIA_DRIVER_CAPABILITIES=compute,utility,graphics`
   - EGL 虚拟显示

3. **动态开关**
   - `.env` 中 `COLMAP_USE_GPU=1/0`
   - 运行时参数：`--SiftExtraction.use_gpu={0|1}`

**性能提升**：
- 特征提取：2.47s → 0.62s（**4× 加速**）
- 特征匹配：20.3s → 3.03s（**6.7× 加速**）

### 6.2 MASt3R 少视角适配

**挑战**：
- COLMAP 需要 ≥20 张图且重叠度高，少视角场景（5-10 张）直接失败
- 传统 SfM 对纹理、光照敏感

**MASt3R 优势**：
- 基于 Transformer 的学习方法，直接预测位姿和几何
- 5 张图即可重建（COLMAP 完全失败的场景）
- 推理速度快（5 张图：13.9s）

**集成方案**：
1. **双后端架构**
   - API 参数：`sfm_backend=colmap|mast3r`
   - 训练侧统一：输出相同的 COLMAP bin 格式

2. **COLMAP 格式转换**
   - MASt3R 输出：`cam2world` 矩阵 + 深度图 + 内参
   - 转换：深度图反投影 → 稀疏点云 → `points3D.bin`

3. **显存优化**
   - 场景图策略：< 20 张用 `complete`，≥20 张用 `swin`
   - 最大图片数限制：15 张（保守值）

**适用场景**：
- 手机随手拍（5-10 张）
- 无法环绕拍摄的场景（建筑外立面、大型设备）
- 快速原型验证

### 6.3 显存优化策略

**约束**：RTX 4060 8GB 显存，需同时容纳模型和训练数据

**优化手段**：

1. **动态降采样**（`downsample` 参数）
   - 1×：原始分辨率（大显存）
   - 2×：1/4 像素（推荐，质量与显存平衡）
   - 4×：1/16 像素（默认，8GB 显存安全值）
   - 8×：1/64 像素（极限节省，质量下降）

2. **高斯数量上限**（`cap_max` 参数）
   - 默认：1,000,000（100 万）
   - 显存不足时建议：500,000（50 万）

3. **gsplat Packed 模式**
   - 紧凑存储格式，省显存
   - MCMC 策略自动剪枝低不透明度高斯

4. **PyTorch 内存池**
   - `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`
   - 减少碎片，提升分配效率

**错误处理**：
- 捕获 `CUDA out of memory` 异常
- 自动附带调整建议：`增大 downsample 或减小 cap_max / iterations`

### 6.4 异步任务管理

**技术选型**：Celery + Redis

**设计要点**：

1. **串行执行**（`concurrency=1`）
   - GPU 独占，避免显存竞争
   - 简化错误处理

2. **实时进度更新**
   - 每步写入 `status.json`
   - API 轮询读取（无需 WebSocket）

3. **任务超时**
   - 硬超时：4 小时（Celery task_time_limit）
   - 防止任务卡死占用资源

4. **错误隔离**
   - 任务失败不影响其他任务
   - 错误信息写入 `status.json` 的 `error` 字段

### 8.3 常见问题排查

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| `No good initial image pair found` | COLMAP 特征匹配失败 | 检查图片重叠度、增加图片数量、切换到 MASt3R |
| `CUDA out of memory` | 显存不足 | 增大 `downsample`（4→8）或减小 `cap_max` |
| `task is running, cannot delete` | 尝试删除运行中任务 | 等待任务完成或失败后再删除 |
| `401 Unauthorized` | API Key 错误 | 检查请求头 `X-API-Key` 是否与 `.env` 一致 |
| `COLMAP feature extractor failed` | GPU SIFT 不可用 | 检查 `NVIDIA_DRIVER_CAPABILITIES` 是否包含 `graphics` |

### 8.4 性能优化建议

**训练速度**：
- 减少 `iterations`（7000 → 5000，质量略降）
- 使用更强 GPU（RTX 4090: 3× 加速）
- 降低 `sh_degree`（3 → 2，颜色细节略降）

**显存占用**：
- 优先调整 `downsample`（质量影响最小）
- 其次调整 `cap_max`（影响高斯密度）
- 最后调整 `iterations`（影响收敛程度）

**磁盘空间**：
- 定期清理 `/data/tasks/` 下的旧任务
- 压缩 COLMAP 中间产物（保留 `colmap.log` 用于排查）
- 限制任务保留时间（7 天自动删除）
